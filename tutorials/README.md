Notebook specification: **DIMER Notebook Specification 2.0** — every notebook is **standalone** (§4): each is generated by
`tools/build_notebook.py` from its own template (`tools/notebook_template.py`, `tools/notebook_template_imputation.py`,
`tools/notebook_template_anomaly_detection.py`, `tools/notebook_template_classification.py`) and carries the repository's package (ten modules; twelve for the classification notebook), model identity, snapshot
manifest and runtime pins, so the exported `.ipynb` keeps working without this repository being reachable. Do not edit a
notebook by hand; edit the package or the template and regenerate (`python tools/build_notebook.py [--template … --out …]`;
`--check` is enforced by the validator and CI).

The three inference notebooks intentionally remain separate because embeddings, imputation, and anomaly scoring have
different input/output and evaluation semantics. Each of them is a `TASK-INFERENCE` workflow: it consumes the pretrained,
immutable `AutonLab/MOMENT-1-base` checkpoint and performs no gradient training, fine-tuning, in-context conditioning, or
fitted preprocessing. The fourth notebook is an `E2E` workflow: it trains the caller's own classification head (and
optionally the last encoder blocks) on a pinned real corpus through `adaptation.py`, and is the only notebook in which
the encoder can change.

## What the classification notebook changes

The inference notebooks report `not-measurable` for embeddings because a vector has no intrinsic metric. The classification notebook keeps that report (Section 5, on real windows) and adds the adaptation contract around it: a real labelled corpus pinned by digest, accuracy and macro-F1 in the carried `adaptation.py` with a majority floor and a k-NN baseline as reference points, a linear probe (frozen policy) and a bounded unfreeze (unfrozen policy) selected on validation, before/after predictions, and an artifact that reloads. `evaluate` is the labelled corpus-level stage (`measured` / `measured-small-sample`). Its conformance notes:

- **Standalone carrier (ST1–ST8):** Section 2 embeds twelve modules (the ten above plus `samples` and `adaptation`) in topological order; Section 3 is the shared model cell (`load_moment(task="embedding", weights_dir=WEIGHTS_DIR)`); `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports; `tools/validate_release_assets.py` checks it against `tools/notebook_template_classification.py` (PAR1–PAR3).
- **Data (DAT1–DAT9, ST6):** the default sample is one pinned object — the UCI HAPT archive (`https://archive.ics.uci.edu/static/public/341/…zip`, 79,596,192 bytes, SHA-256 `4ac4ae06…`), CC BY 4.0 per the UCI licence notice — refused on any mismatch before it is opened and read without extraction; `read_corpus` cuts 179 windows by an a-priori rule (per volunteer and activity, the centre 512 samples of the first labelled segment at least 512 samples long), `build_sample_dataset` draws 18 / 6 / 6 whole volunteers (107 / 36 / 36 windows), `check_split_disjoint` asserts no shared window (by sample digest) and no shared volunteer. The template adds a second *External access* bullet naming the host, the byte count and the licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `class_names` + `check_split_disjoint` + `user_summary` + refusal probes (validation, with three digests) → `records_to_long_frame` + `validate_inputs` + `validate_long_frame` + `to_windows` + `embed` + `evaluation_report` + `build_provenance` (inference contract, the package's own path) → `majority_baseline` + `knn_baseline` + `adapt(trainable_blocks=0)` + `evaluate` (floor, baseline and frozen policy) → `adapt(trainable_blocks=TRAINABLE_BLOCKS)` (unfrozen policy, selected on validation) → `evaluate` on validation and test with the comparison (evaluation) → `classify` before (a fresh `load_moment` instance with the probe adapter) and after → `save_artifact` → `load_artifact` on a fresh instance with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the trained head's softmax is an argmax rule, not a calibrated confidence; a cosine is a similarity, not a score; accuracy and macro-F1 are computed over one labelled set with a fixed class order; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the majority floor, the k-NN vote and the frozen policy are scored on the same 36 test windows as the selected policy, per-class recall is printed beside every accuracy, the selection rule is stated (lowest validation log-loss, probe competing as epoch 0) and the notebook asserts only that the probe and the selected model beat the floor — a gain over the probe is the question, not an assertion; every metric is labelled as one seeded split of one small corpus with no dispersion estimate (one window ≈ 2.8 points).
- **Split integrity (SPL1–SPL8):** the split is seeded, drawn by whole volunteers and window-disjoint by sample digest; validation selects the epoch and policy and the test split is used for nothing but the final evaluation, the before/after predictions and the reload-parity check; the notebook states that real data must be split by person, device or session.
- **Ceilings (VAL6):** the package's `max_windows` (1,024), `max_channels` (32) and `max_rows` (5,000,000), the record bounds (8..1,024), the class bounds (2..100), the window length (512) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one long-frame refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user windows flow through the same validation, seeded group-disjoint split (the loader refuses a `records.csv` row without a non-empty `group`, so the person-disjoint guarantee holds for BYOD as it does for HAPT; `require_group=False` is the explicit opt-out), floors, both policies, evaluation, prediction, export and reload cells; arrays inside the uploaded zip are decoded from the archive, never extracted, and the training records table is written to `outputs/moment_classification_train.csv` in that shape.
- **Representation finding:** MOMENT instance-normalises every window before patching, so the constant gravity component that separates the HAPT static postures never reaches the encoder — both policies separate the walking activities almost perfectly and confuse sitting / standing / laying; the notebook states this as a property of the normalisation, not of the head.

## Conformance notes

_Requirement identifiers in these notes (for example `ST1`, `PAR3`, `DAT24`, `EVAL21`) are the NOTEBOOK_SPEC 1.1 numbering they were written against; NOTEBOOK_SPEC 2.0 renumbered its sections and the pull request that migrated this repository reports conformance against the 2.0 pre-flight checklist (§26) and report format (§30)._

- **Standalone carrier (ST1–ST6):** the primary path performs no clone, repository install, or repository import. Section 2 of every notebook is `src/moment_pipeline/` verbatim — ten cells tagged `metadata.dimer.embedded_module`, one per module in dependency order (`config`, `model`, `validation`, `canonical`, `csvio`, `embedding`, `provenance`, `imputation`, `anomaly`, `roles`); the only rewrites make the default weights directory working-directory-relative and remove the package-relative `from .x import` lines, whose names the preceding cells already define. Section 3 carries the model identity and the 3-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins — `momentfm` as the `[tool.uv.sources]` commit-pinned direct reference `momentfm @ git+https://github.com/moment-timeseries-foundation-model/moment@38f7310ad594100747ca2a8357e9c7ca7d323e0e` (no usable PyPI release exists; RFC M-7). `metadata.dimer.generated_from` records the repository, the generating commit, the ten module paths, their combined SHA-256, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` (primary notebook) and `tools/validate_release_assets.py` (all three) fail when any carried module, the inline manifest, or the inline pins differ from the repository, or when a notebook is not byte-identical to the generator's output from its template.
- **Model acquisition:** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry against the manifest **and** asserts the manifest digests equal the package's own `PINNED_*` constants; `load_moment(task=…, weights_dir=WEIGHTS_DIR)` loads the verified directory through the pinned `momentfm` package (`MOMENTPipeline.from_pretrained` on the local directory; the task head is part of the loaded model's identity) and proves the live weights are the pinned checkpoint's. The notebooks' only external dependencies are the pinned PyPI distributions, the commit-pinned `momentfm` source, and the Hub at that revision.
- **Role stages:** `validate_inputs` (DAT24) writes `outputs/<stem>_input_manifest.json` with the schema and ceilings, per-window observations (series, valid positions, padding, truncation), source-missingness fractions, verdict, and one recorded rejection finding (an empty channel); `evaluation_report` (EVAL21) writes `outputs/<stem>_evaluation_report.json` — `not-measurable` for embeddings (representations), `sample-sanity` with `masked_point_metrics` and the linear-interpolation baseline for imputation, `sample-sanity` with `top_k_recall` for the labelled anomaly sample and `not-measurable` for unlabelled BYOD, each stating what would make the task measurable.
- The default samples are the repository's deterministic synthetic tables regenerated in code and digest-asserted against `examples/sample-data/SHA256SUMS` (no download); their metrics are sanity evidence for the input contract and the task paths, not correctness or benchmark claims.
- Task obligations (Notebook Specification §20.4 imputation: masking unit, source-missing vs artificial masking, withheld-truth-only evaluation, observed values preserved, requested-to-effective mask accounting; §20.5 anomaly scoring: score definition and direction, no shipped threshold, no threshold presented as universal, falsifiable ranking on a labelled sample; §20.6 embeddings: shape, pooling, per-window unit, missingness visibility, representations-not-predictions, identifiers exported beside vectors) are stated in each notebook's prose and enforced by the validator's markers.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; `DIMER_BYOD_PATH` is an automation hook read from the environment.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
